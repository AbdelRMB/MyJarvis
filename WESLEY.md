# Wesley — instructions pour Wesley

> À lire en premier avant de travailler sur ce projet, et à suivre avant tout le reste.
> Wesley (et les agents de code qu'il pilote) le tiennent à jour à chaque modification du projet.

## Présentation
Wesley lui-même : assistant personnel de bureau (Python + interface React) pour macOS (puce Apple) et Windows,
avec une appli mobile web (`interface/mobile`) et un serveur de comptes (`serveur/`).
Le guide complet (installation, construction, règles du dépôt) est dans `CLAUDE.md` : il s'applique aussi ici.

## Commandes utiles
- `cd interface && npx tsc -p .` : vérifier les types de l'interface (bureau + mobile) avant chaque commit
- `cd interface && npm run build` : compiler l'interface de bureau dans `wesley/static` (committée)
- `cd interface && npm run build:mobile` : compiler l'appli mobile dans `serveur/mobile` (committée)
- `python -m pytest tests -q` : tests du cœur Python (pytest et numpy)
- `python -m pytest tests/test_transcription.py -q` : transcription seule (diarisation, Whisper simulé, découpage, lecture par parties, choix du modèle, reprise, phrases perdues)
- Sur la machine du mainteneur, pytest + numpy sont dans `../Wesley/.venv/bin/python` (le Python système n'a pas pytest) ; `.venv-mac` a toutes les dépendances de l'appli (pour importer les outils)
- `npm run build` ne suffit pas quand `en.ts` change : l'appli mobile l'importe aussi, relancer `npm run build:mobile`
- `cd serveur && WESLEY_DB=/tmp/wesley-test.db python -m pytest tests -q` : tests du serveur de comptes (dont `test_partages.py`)
- `python -m pytest tests/test_partage.py -q` : tâches et transcriptions partagées entre appareils (pytest + cryptography)
- `python -m pytest tests/test_resume_transcription.py tests/test_recherche_et_fins.py -q` : résumé (cerveau simulé), recherche, notifications de fin, lancement à distance, enregistrement du téléphone

- `tests/conftest.py` neutralise `notifications.ajouter` et `annonces.annoncer` pour TOUS les tests : `notifications.json` est versionné dans le dépôt (dossier de dev = RACINE), un test ne doit jamais l'écrire. Lancer l'appli en dev (port 7788) l'écrit aussi : `git checkout -- notifications.json` après un essai
- Ce PC Windows du mainteneur a maintenant un `.venv` complet (`py -3.12 -m venv .venv` + requirements.txt + requirements-voix.txt) : `.venv/Scripts/python -m pytest tests -q`. ## Conventions
- Messages, commits, CHANGELOG et textes de l'interface en français ; traductions anglaises dans `interface/src/lib/en.ts` (mobile : `en-mobile.ts`).
- Un changement de l'appli = nouvelle version dans `wesley/version.py` + section `## x.y.z` en haut de `CHANGELOG.md`, écrite pour l'utilisateur.
- Jamais de données personnelles ni de secrets dans git (`.env`, `config.json`, `memoire/`, `logs/`, `comptes/`, fichiers de déploiement du serveur).
- Serveur de comptes : n'utiliser que **GET, POST et PUT** (`compte._appel` côté bureau, `api()` dans `interface/mobile/src`). Le proxy Apache devant l'API renvoie un 404 HTML à toute autre méthode (PATCH, DELETE…), vu dans Wesley comme « Erreur du serveur (404) sur … ». Pour modifier ou supprimer : `POST /v1/…/{id}` ou `POST /v1/…/{id}/supprimer`. Vérifié par `tests/test_methodes_serveur.py`.
- Un outil de Wesley = une fonction décorée `@outil` dans `wesley/outils/` (docstring : 1re ligne = description, puis `param: description`), module ajouté à `charger_tous()`.

## Décisions
- Transcription de réunions (`wesley/transcription.py`) : 100 % local. Whisper (faster-whisper) + empreintes vocales sherpa-onnx (WeSpeaker CAM++, ONNX ~28 Mo téléchargé dans `RACINE/modeles` au 1er usage ; à défaut, empreinte spectrale numpy, moins précise). Nombre de personnes imposable. Pas de pyannote (torch, jeton Hugging Face).
- Son de l'ordinateur : ScreenCaptureKit via pyobjc sur Mac (autorisation Enregistrement de l'écran, pas de pilote), WASAPI loopback via PyAudioWPatch sur Windows, périphérique loopback (BlackHole, VB-Cable…) en secours. Les sources passent par un `Mixeur` calé sur l'horloge (WASAPI n'envoie rien quand le PC est muet). Les rappels Objective-C doivent renvoyer `None` (sinon plantage).
- Diarisation (2.4.0) : jamais de lien moyen entre phrases (des empreintes de 2 s d'une même voix ne se ressemblent qu'à ~0,4 : un prof seul donnait des dizaines de locuteurs). On compare des **voix moyennes pondérées par la durée** (centroïdes) : `regrouper` = fenêtres de phrases consécutives (≤ 12 s) → hiérarchique sur les fenêtres ≥ 3 s (`DUREE_SOLIDE`), seuil = `_assoupli(seuil, 1.1)` (0,45 pour CAM++) → fenêtres courtes rattachées → locuteurs marginaux fusionnés (< min(15 s, 3 %) si voix pas nettement différente, < min(6 s, 1 %) toujours) → lissage des passages < 3 s. Les seuils passent par `_assoupli` (échelle en 1 - cosinus) pour valoir aussi pour l'empreinte spectrale (seuil 0,95). En direct (`Diariseur`) : création seulement sur phrase ≥ 3 s, bonus de continuité, fusion des voix proches, `regrouper_tout` toutes les max(10, n/20) phrases ; `etiquettes` = locuteur à jour de chaque phrase. Phrase sans empreinte : `regrouper_complet` lui donne le locuteur voisin (avant, elle faisait sauter le regroupement final). Testé sur empreintes simulées façon CAM++ (bruit ∝ 1/√durée, dérive, 10 % aberrantes) : 1 voix → 1, prof + 2 élèves → 3.
- Texte fidèle (2.4.0) : `options_whisper` (température 0, faisceau 5, `condition_on_previous_text=False`, seuils no_speech/logprob/compression, VAD 500 ms, horodatage par mot, `hallucination_silence_threshold`), options inconnues de faster-whisper filtrées par signature. `decouper_phrases` écarte les segments douteux, coupe aux pauses ≥ 0,8 s et à 30 s, retire boucles (`sans_boucles`) et hallucinations ; jamais de reformulation. Amorce (`initial_prompt`) = titre + `vocabulaire()` (mots de l'utilisateur, mots techniques entendus 2 fois, thème du titre), jamais le texte précédent ; une phrase qui recopie l'amorce est écartée. Modèle « auto » (`modele_auto`) : large-v3-turbo si ≥ 8 Go et ≥ 8 cœurs (ou fichier importé), sinon small/base ; pas de distil-large-v3 (anglais seulement). Langue : celle de Wesley par défaut, « » = détection. Réglage du modèle : `modele_par_defaut()` ne garde `transcription_modele` que si `transcription_modele_choisi` est vrai (posé par l'interface depuis 2.4.0) ; avant, l'interface enregistrait d'office le modèle affiché (souvent « small »), ces anciens réglages repassent donc en « auto ».
- Renumérotation : les locuteurs sont toujours numérotés 1..N sans trou, dans l'ordre de première apparition (`renumeroter`), en direct (`appliquer_fusion` décale les numéros au-dessus du locuteur fusionné, `regrouper_tout` renumérote) comme après le regroupement final, le regroupement refait à la demande et la reprise d'une transcription interrompue. Test de non-régression : `test_renumerotation_apres_12_locuteurs_crees_puis_fusionnes`.
- Affichage / lecture : tours de parole coupés à 2 s de pause et 30 s (`tours_de_parole`) ; `extrait()` sert `lire_transcription` par parties de ~9 000 caractères (`partie`) ou par minutes (`debut`/`fin`) : la sortie des outils est tronquée à 12 000 caractères (`outils/__init__.py`), un outil qui peut renvoyer plus doit paginer.
- Données : `RACINE/transcriptions/<id>.json` + `<id>.npz` (empreintes, jamais le son ; `valides` marque les phrases sans empreinte) ; fichier lisible `.md` réécrit au fil de l'eau dans `~/Documents/Wesley/Transcriptions` (`CONFIG["dossier_transcriptions"]`). Pendant une transcription au micro, l'écoute « Wesley » est coupée.
- Découpage des réunions (`Decoupeur`) : seuil d'énergie volontairement bas (bruit × 2,5, plancher 0,003) et volume remonté jusqu'à ×20 avant Whisper, pour ne pas perdre les voix lointaines en réunion physique ; le filtre VAD de Whisper écarte le bruit seul. Testé : conversation à 3 % du volume transcrite.
- Phrases perdues (2.5.0) : chaque filtre doit viser l'invention, pas un mot. `_HALLUCINATIONS` = motifs précis (génériques « sous-titres réalisés par », Amara, musique/ponctuation seules) ; `_HALLUCINATIONS_VIDEO` (« abonnez-vous », « merci d'avoir regardé »…) seulement dans une phrase de ≤ 12 mots. `recopie_consigne` : seulement le titre entier, « Vocabulaire… » ou une liste d'au moins 3 mots à virgules de l'amorce (avant, « le constructeur » était jeté). Doublon de Whisper = même texte collé (< 1 s). Whisper qui lève une exception : 2e essai sans amorce. À l'arrêt, 0,3 s de son encore en route est lue. `Tampon` : 15 s d'avance tolérées (`RETARD_MAX`, garde 3 s, compteur `perdu`). VAD seuil 0,35, `speech_pad_ms` 400. `segment_douteux` (lp < -1,4) inchangé : c'est ce qui évite les mots inventés.
- Reprise (2.5.0) : `reprendre(tid)` / `Transcription.reprise(session)` continue la même session (même id, fichier, noms, date de début) ; horodatage = max(durée, fin de la dernière phrase), `session["reprises"]` = [{position, date}] (repère dans l'export et l'interface, les tours de parole ne passent jamais à cheval). Les phrases d'avant ne changent jamais de locuteur (noms, fusions, corrections gardés). Le diariseur est amorcé avec les empreintes du .npz (`Diariseur.amorcer`) ; `rattacher` donne aux voix regroupées avec des phrases d'avant leur ancien locuteur (majorité en durée, ≥ min(3 s, 25 %) de la voix), et aux nouvelles N+1, N+2… Sans .npz, ou si l'extracteur de voix a changé (`session["empreinte"]`), pas d'amorce : la suite prend de nouveaux numéros. Champs manquants des anciennes sessions remplis par défaut. API `POST /api/transcriptions/{id}/reprendre` (source d'origine, micro pour un fichier), outil `reprendre_transcription`. `duree` est maintenant tenue à jour pendant l'enregistrement (et réparée par `au_demarrage`).
- Onglet Transcription (2.5.0) : colonne de gauche = un seul défilement (lancement + liste) ; bloc de droite `overflow-y-auto` avec un texte d'au moins 16 rem qui défile seul ; panneau des locuteurs ≤ 35 %.
- WESLEY.md : priorité sur la mémoire, les autres fichiers et les règles par défaut, mais la demande en cours et les consignes personnelles de l'utilisateur passent avant.
- Tâches de code : si l'agent n'a pas mis à jour le WESLEY.md, Wesley le relance une fois, puis l'y consigne lui-même avant le commit final.
- Partage entre appareils (2.6.0, `wesley/partage.py`) : chaque ordinateur publie ses tâches et transcriptions dans le compte (`PUT /v1/partages/{tache|transcription}/{id}`, table `partages` du serveur), chiffrées avec la clé du coffre (AES-GCM, données associées `wesley-partage`, JSON compressé zlib : le téléphone le lit avec `DecompressionStream("deflate")`). Résumé et contenu séparés : la liste reste légère, le contenu (journal ≤ 400 entrées, segments + locuteurs) se lit à la demande. Un élément appartient à la session qui l'a publié (`appareil`) ; `resume.machine` = `RACINE/appareil.id`, stable d'une reconnexion à l'autre (`reconcilier` reprend ses anciens éléments, republie ce qui a changé hors ligne et retire ce qui a été supprimé). Publication différée (2 s ; 10 s pour une transcription en cours), retirée de la file AVANT l'envoi pour ne jamais perdre la fin. Le serveur a un compteur à part (`/v1/attendre?partages=` = MAX(modifie), suppression = pierre tombale datée) : une transcription en cours ne déclenche pas de synchro complète de la mémoire. Actions sur l'élément d'un autre appareil : ordre chiffré `{"type": "partage", genre, id, action, params}` à l'appareil d'origine (`partage.agir` → `appareils.envoyer` → `partage.executer` chez lui) ; avant l'envoi, `agir` vérifie qu'il est connecté au compte, en ligne et accepte les ordres, et toute erreur remonte sous la forme « Impossible de … sur X : raison » / « X n'a pas pu … : raison » (HTTP 409 côté interface). Lecture et export d'une transcription d'un autre appareil se font en local à partir de la dernière version publiée (même si l'autre est éteint). Mobile : `interface/mobile/src/moteur/partages.ts`, vues `Taches.tsx` et `Transcriptions.tsx`, outils `lister_*`, `suivre_tache`, `lire_transcription`, `reprendre_*`, `arreter_*`.

- Résumé (2.7.0, `wesley/resume_transcription.py`) : pas seulement les réunions. Le cerveau reconnaît le genre (cours, réunion, discussion, appel, entretien, conférence, note vocale, autre) et adapte la forme ; consigne stricte « ne résume que ce qui a été dit ». Réponse = Markdown + bloc ```json final {genre, titre, actions[]} lu de façon tolérante (`analyser`, petits modèles locaux). Plus de 40 000 caractères : notes par morceaux (coupés aux fins de ligne) puis résumé des notes. Rangé dans `session["resume"]` (`transcription.marquer_resume`, sous `_verrou` : l'ancien résumé reste affiché pendant qu'on le refait, l'erreur est gardée dans `erreur`), donc partagé et en tête de l'export. Auto à la fin (`web._apres_transcription` → `au_terme`, ≥ 4 phrases et ≥ 30 s, réglage `transcription_resume_auto`) ; actions → À faire seulement au premier résumé auto (`afaire_ajoutees`, réglage `transcription_actions_afaire`). Bouton/outil : `web.lancer_resume` (en fond), `resumer_transcription`.
- Recherche (2.7.0, `wesley/recherche_transcriptions.py`, copie côté téléphone dans `moteur/partages.ts`) : mots sans accents, mots vides ignorés, début de mot + pluriel simple, au moins la moitié des mots par prise de parole, bonus titre/résumé. Route `/api/transcriptions/chercher` déclarée AVANT `/api/transcriptions/{tid}`.
- Lancement à distance (2.7.0) : `partage.lancer(appareil_id, genre, params)` → ordre `partage` avec `id` vide et `action: "demarrer"` ; l'autre ordinateur utilise SON modèle Whisper. `/api/appareils/ordinateurs` = liste légère pour les menus « Sur … ».
- Téléphone comme micro (2.7.0) : MediaRecorder (webm/opus ou mp4/aac, 32 kb/s, sans suppression de bruit, écran maintenu allumé), envoi en morceaux de 4 Mo par ordres `partage`/`audio` (`partage.recevoir_audio` : assemblage dans `transcriptions/imports/<envoi>.part`, transcription au dernier morceau). En mode « confirmation », seule la 1re partie est confirmée (`appareils._envois_acceptes`) ; journal et notification au dernier morceau seulement. Limite : l'appli web s'arrête si l'écran se verrouille.
- Notifications de fin (2.7.0) : `partage.fins(avant, apres)` (même règle dans `moteur/partages.ts`) : transitions en_cours → fini et apparition d'un résumé, jamais au premier chargement. Sur le téléphone, pas de Web Push : seulement appli ouverte ou en mémoire.
- GPU Mac (2.7.0) : `modeles.charger_whisper(gpu=True)` essaie `device="mps"` si `ctranslate2.get_mps_device_count()` > 0 (CTranslate2 ≥ 4.x compilé avec MPS), sinon processeur. Réglage `transcription_gpu`, désactivé par défaut, jamais mesuré sur un vrai Mac.
- Déploiement du serveur : `deployer.sh` copie les sous-dossiers de `mobile/` (find) et vide `mobile/` sur le VPS avant l'envoi. Les fichiers du VPS appartenaient à l'uid 501 (copie depuis un Mac) : rendus à `abdel` le 2026-11-24 ; ne plus copier depuis le Mac avec sudo.

- Mémoire par le sens (2.8.0, `wesley/semantique.py`) : multilingual-e5-base ONNX quantifié (Xenova, ~270 Mo, téléchargé dans `RACINE/modeles`), onnxruntime + tokenizers (déjà livrés), préfixes e5 « query: »/« passage: », moyenne masquée, 2 fils, déchargé après 10 min. Choisi après essai contre e5-small et paraphrase-multilingual-MiniLM sur des souvenirs réels (5/6 contre 3/6). Scores serrés (~0,75 sans rapport, ≥ 0,78 lié) : seuils 0,77 (souvenirs), 0,80 (historique), 0,78 (documents) + 0,08 × part de mots exacts. Vecteurs gardés par empreinte du texte (`index_<nom>.npz`, float16). Sans modèle : recherche par mots (même résultat qu'avant).
- Souvenirs et instructions (2.8.0) : au-delà de 40 souvenirs, les instructions ne gardent que l'identité + les 25 plus utilisés (`faits_du_prompt`) ; `memoire.rappel_pour(texte)` joint à la demande consignes + 6 souvenirs proches + propositions à confirmer. Chez Claude c'est le message système `clear_at: next_user_message` existant : le cache du préfixe reste valable. « journal » (résumés de semaine) jamais dans les instructions. Extraction de souvenirs : `profil_texte(complet=True)`.
- Rangement (2.8.0, `wesley/consolidation.py`, 1×/jour, 5-15 min après le lancement puis toutes les 6 h) : paires ≥ 0,93 = doublons probables, 0,86-0,93 de même catégorie = à vérifier ; le cerveau décide (« distincts » dans le doute). Fusions appliquées seules (rien perdu), contradictions = propositions (`RACINE/memoire/consolidation.json`) jamais appliquées sans accord (écran Mémoire ou outil `confirmer_memoire`, posée une fois dans la conversation) ; une proposition refusée n'est jamais reposée. Résumé de la semaine passée = souvenir « journal » « Semaine du JJ/MM/AAAA : … ». Habitudes (`habitudes.py`) : même demande ≥ 4 jours sur 21, à ±60 min de la médiane → proposition « routine » (accepter = automatisation horaire 5 min avant, au quart d'heure).
- Leçons (2.8.0, `apprentissage.py`) : déclenché si correction (regex) avec une réponse précédente, ou outil en erreur puis outil réussi dans le même échange ; le modèle rapide dit s'il y a une leçon réutilisable ; pas de doublon (≥ 0,92 de sens). Branché dans `Wesley.demander` (wrapper de `_demander`, trace des outils), donc tous les cerveaux.
- Coûts (2.8.0, `claude.py`) : `completer` (travail de fond) sur Haiku 5.5, effort low, max_tokens 16000 (la réflexion compte dedans). Budget mensuel : alerte 80 %, puis conversation sur Haiku jusqu'au mois suivant ; changement de modèle = conversation neuve (`histo_claude` vidé : la réflexion signée par l'autre modèle et son cache ne servent plus). Sur Haiku : PAS de `fallbacks` ni du beta server-side-fallback (pas de secours côté serveur), pas de conseiller, outils web de base `web_search_20250305`/`web_fetch_20250910` (les variantes 20260209 ne sont pas disponibles sur Haiku). Vérifié dans la doc de l'API (skill claude-api).
- Automatisations (2.8.0) : déclencheurs `rendez_vous` (connecteur Agenda relu toutes les 10 min), `fichier` (taille stable sur 2 passages, téléchargements en cours ignorés ; ce qui est là à la création ne compte pas), `tache_finie` (locales + autres appareils), `site` (alerte au passage OK→KO, annonce au retour). `condition` en français vérifiée par le cerveau AVANT d'agir (doute ou panne du cerveau = on ne fait rien). Bilan du soir : réglages `bilan_soir`/`bilan_soir_heure` (outil `bilan_du_soir`).
- Telegram (2.8.0, `telegram.py`, connecteur) : liaison par code à 6 chiffres affiché dans l'état du connecteur (« /start CODE ») ; tout autre compte est ignoré sans réponse. Un seul ordinateur répond (`appareil`, posé par le premier qui démarre le bot ; « Conflict » de Telegram signalé). Un agent Wesley par conversation, remis à zéro après 1 h. Vocaux transcrits par Whisper local ; fichiers dans ~/Downloads/Telegram. `transmettre_annonce` (appelé par `annonces.annoncer`) si « annonces » = oui. Paramètre `delai` (et pas `timeout`, qui est un paramètre de getUpdates).
- Connecteurs simples (2.8.0, `connecteurs_maison.py`) : Home Assistant (URL + jeton longue durée : `ha_etats`, `ha_action`) et Discord/Slack par webhook (`salon_envoyer`). Enregistrés en fin de `connecteurs.py` (import après la classe de base). Pas d'OAuth : Google Agenda en écriture, Outlook / Microsoft 365, Spotify et Drive demandent une application déclarée chez Google / Microsoft / Spotify (voir Pistes) ; en attendant, un serveur MCP les couvre (connecteur MCP).
- Documents (2.8.0, `documents.py`) : dossiers dans `dossiers_documents`, PDF (pypdf, ajouté aux requirements), docx/odt lus comme zip+XML, txt/md/csv/rtf ; passages ~1 200 caractères avec la page ; index `RACINE/memoire/documents.json` relu toutes les 30 min (seuls les fichiers changés), vecteurs dans `index_documents.npz`.
- Ctrl+Alt+E (2.8.0, `contexte.py`, raccourci `raccourci_contexte`) : copie de la sélection par Ctrl/Cmd+C simulé avec un marqueur dans le presse-papier (rien de sélectionné = marqueur inchangé), presse-papier d'avant remis ; événement `contexte` → bandeau dans l'Assistant.
- Annuler (2.8.0, `annulation.py`) : chaque demande = un « tour » (`nouvelle_demande` dans `Wesley.demander`) ; copie avant écriture (≤ 200 Mo), corbeille de Wesley pour `supprimer` (14 jours, puis corbeille du système), jamais d'écrasement de ce qui est revenu entre-temps. Dossier `annulation/` ignoré par git.
- Actions à l'écran (2.8.0) : clic, saisie, raccourci et cliquer_element ajoutent « fenêtre au premier plan » à leur résultat (`controle._apres`), consigne de regarder l'écran si ce n'est pas la bonne.
- Santé (2.8.0, `sante.py`) : par jour, outils (appels, échecs = résultat qui commence par Erreur/Impossible…, durée, dernière erreur) et cerveaux, 30 jours, écrit toutes les 30 s au plus ; joint au diagnostic des tickets (avec accord). CI : job `e2e` (types, tests du serveur, téléphone Playwright) requis avant Windows et Mac.

## Pistes
- Notifications sur le téléphone appli fermée : Web Push (VAPID) côté serveur, avec un texte générique (le serveur ne doit pas lire les titres). En attendant, Telegram (2.8.0) reçoit les annonces.
- Connecteurs OAuth (Google Agenda en écriture, Outlook / Microsoft 365, Spotify, Google Drive / OneDrive) : déclarer une application chez chaque fournisseur (identifiants client), puis flux OAuth « appareil » ou redirection locale.
- Appli mobile native (Capacitor) avec mises à jour du JavaScript sans App Store : discutée, mise de côté pour l'instant.
- Résumé : à juger sur de vrais cours / réunions avec chaque cerveau (Claude, Ollama…) ; les tests utilisent un cerveau simulé.
- Accélération sur Mac : option `transcription_gpu` (2.7.0) à mesurer sur un vrai Mac (retard affiché pendant une transcription, avec et sans) avant de l'activer par défaut.
